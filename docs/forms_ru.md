# React Формы

## 🧠 Описание задачи

В этой задаче вам предстоит реализовать обработку форм двумя разными способами: с помощью неконтролируемых компонентов и React Hook Form. Вы создадите доступные модальные окна с использованием React Portals, реализуете комплексную валидацию и управление данными форм с помощью библиотек управления состоянием.

## Функциональные требования (максимум **100 баллов**)

### Функция 1: Модальное окно с React Portals (**15 баллов**)

**Как** пользователь
**Я хочу** открывать формы в доступных модальных окнах
**Чтобы** заполнять формы, не покидая главную страницу

**Сценарий:** Отображение модального окна и доступность

- **Дано** я нахожусь на главной странице
- **Когда** я нажимаю кнопку для открытия формы
- **Тогда** открывается модальное окно с использованием React Portal
- **И** модальное окно является доступным (управление фокусом, закрытие по ESC, закрытие по клику вне окна)
- **И** один и тот же компонент модального окна может отображать обе реализации: неконтролируемую форму и форму с React Hook Form

**Критерии приемки:**

- Создан универсальный, переиспользуемый компонент модального окна с использованием React Portal. [6 баллов]
- Модальное окно доступно благодаря правильному управлению фокусом. [3 балла]
- Поддержка закрытия по клавише ESC. [3 балла]
- Реализована возможность закрытия по клику вне области модального окна. [3 балла]

### Функция 2: Управление состоянием (**15 баллов**)

**Как** разработчик
**Я хочу** хранить отправленные данные форм в библиотеке управления состоянием
**Чтобы** отображать отправленные данные на главной странице

**Сценарий:** Хранение данных формы

- **Дано** я реализовал формы с использованием неконтролируемого подхода и React Hook Form
- **Когда** форма успешно отправлена
- **Тогда** данные формы сохраняются в Redux или Zustand
- **И** сохраняются все успешные отправки (история)
- **И** отправленные данные отображаются на главной странице в виде плиток или карточек

**Критерии приемки:**

- Redux Toolkit или Zustand настроен и сконфигурирован. [5 баллов]
- Данные формы из неконтролируемой формы сохранены в библиотеке управления состоянием. [3 балла]
- Данные формы из React Hook Form сохранены в библиотеке управления состоянием. [3 балла]
- Все отправленные данные отображаются на главной странице. [4 балла]

### Функция 3: Базовые поля формы (**15 баллов**)

**Как** пользователь
**Я хочу** заполнять базовые поля формы
**Чтобы** предоставить свою личную информацию

**Сценарий:** Ввод базовых данных

- **Дано** я открыл модальное окно с формой
- **Когда** я заполняю форму
- **Тогда** я могу ввести имя, возраст, email, пол и принять условия использования
- **И** все поля имеют правильные подписи, связанные с полями ввода (с использованием `htmlFor`)

**Критерии приемки:**

- Для неконтролируемой формы реализованы поля: имя, возраст, email, выбор пола, чекбокс согласия с условиями. [5 баллов]
- Для формы React Hook Form реализованы поля: имя, возраст, email, выбор пола, чекбокс согласия с условиями. [5 баллов]
- Все поля корректно собирают данные. [3 балла]
- Подписи правильно связаны с полями ввода через `htmlFor`. [2 балла]

### Функция 4: Расширенные поля формы (**25 баллов**)

**Как** пользователь
**Я хочу** загрузить изображение, задать пароли и выбрать страну
**Чтобы** заполнить свой профиль полностью

**Сценарий:** Ввод расширенных данных

- **Дано** я заполняю форму
- **Когда** я взаимодействую с расширенными полями
- **Тогда** я могу загрузить изображение (с проверкой типа и размера, преобразованием в base64)
- **И** я могу задать пароли с индикатором сложности
- **И** я могу выбрать страну из выпадающего списка с автодополнением

**Критерии приемки:**

- Поле загрузки изображения реализовано для неконтролируемой формы с валидацией (тип: png/jpeg, проверка размера). [3 балла]
- Поле загрузки изображения реализовано для React Hook Form с валидацией (тип: png/jpeg, проверка размера). [3 балла]
- Изображение преобразуется в base64 и сохраняется в хранилище. [4 балла]
- Изображение отображается на главной странице после отправки формы. [3 балла]
- Поля пароля (пароль и подтверждение пароля) реализованы для неконтролируемой формы. [2 балла]
- Поля пароля (пароль и подтверждение пароля) реализованы для React Hook Form. [2 балла]
- Отображается индикатор сложности пароля (показывает: 1 цифра, 1 заглавная буква, 1 строчная буква, 1 специальный символ). [4 балла]
- Автодополнение выбора страны реализовано для неконтролируемой формы со списком стран, хранящимся в библиотеке управления состоянием. [2 балла]
- Автодополнение выбора страны реализовано для React Hook Form со списком стран, хранящимся в библиотеке управления состоянием. [2 балла]

### Функция 5: Валидация формы (**15 баллов**)

**Как** пользователь
**Я хочу** видеть ошибки валидации четко
**Чтобы** знать, что необходимо исправить

**Сценарий:** Валидация формы

- **Дано** я заполняю форму
- **Когда** я ввожу неверные данные или отправляю форму
- **Тогда** ошибки валидации отображаются единообразно
- **И** валидация использует схему Yup или Zod
- **И** кнопка отправки формы в React Hook Form отключена при наличии ошибок (мгновенная валидация)
- **И** неконтролируемая форма выполняет валидацию только при отправке

**Правила валидации:**

- Имя: первая буква должна быть заглавной
- Возраст: должно быть число, неотрицательное значение
- Email: базовая проверка email (один @, непустая локальная часть, домен содержит хотя бы одну точку, без регулярных выражений)
- Пароли: должны совпадать
- Изображение: проверка размера и расширения (png, jpeg)
- Страна: должна существовать в сохраненном списке стран

**Критерии приемки:**

- Схема валидации реализована с помощью Yup или Zod для неконтролируемой формы. [3 балла]
- Схема валидации реализована с помощью Yup или Zod для React Hook Form. [3 балла]
- Сообщения об ошибках отображаются единообразно (над или под полями) без скачков верстки. [3 балла]
- Кнопка отправки в React Hook Form отключена при наличии ошибок валидации (мгновенная валидация). [3 балла]
- Неконтролируемая форма выполняет валидацию только при отправке (кнопку отправки отключать не нужно). [3 балла]

### Функция 6: Отправка формы и отображение данных (**10 баллов**)

**Как** пользователь
**Я хочу** отправлять формы и видеть мои данные
**Чтобы** подтвердить, что отправка прошла успешно

**Сценарий:** Успешная отправка формы

- **Дано** я заполнил форму корректными данными
- **Когда** я отправляю форму
- **Тогда** модальное окно закрывается
- **И** данные формы отображаются на главной странице
- **И** только что отправленные данные визуально выделяются (например, другой цвет рамки или фона на несколько секунд)

**Критерии приемки:**

- При успешной отправке модальное окно закрывается, форма сбрасывается. [4 балла]
- Отправленные данные отображаются на главной странице. [3 балла]
- Вновь отправленные данные имеют визуальное выделение (например, цветную рамку или фон). [3 балла]

### Функция 7: Покрытие тестами (**5 баллов**)

**Как** разработчик
**Я хочу** иметь полное покрытие тестами для форм и модальных окон
**Чтобы** обеспечивать надежность и отлавливать регрессии

**Сценарий:** Тестирование форм и модальных окон

- **Дано** я реализовал формы и модальные окна
- **Когда** я запускаю тесты
- **Тогда** компоненты форм, компоненты модальных окон, управление состоянием и вспомогательные функции покрыты тестами

**Критерии приемки:**

- Компоненты форм протестированы (рендеринг, валидация, отправка). [2 балла]
- Компоненты модальных окон протестированы (открытие/закрытие, доступность, рендеринг через портал). [1 балл]
- Управление состоянием протестировано (действия, редюсеры, селекторы). [1 балл]
- Вспомогательные функции протестированы (сложность пароля, преобразование изображения, хелперы валидации). [1 балл]

## 📚 Часто задаваемые вопросы (FAQ)

### ❓ Должно ли модальное окно закрываться, а форма сбрасываться после успешной отправки?

Да. Закройте модальное окно и очистите форму.

### ❓ Мы сохраняем только последнюю отправку или все отправки?

Сохраняйте все успешные отправки (историю) и отображайте их на главной странице.

### ❓ Разрешены ли Tailwind или библиотеки иконок (например, lucide-react)?

Да. Они не являются библиотеками компонентов UI.

### ❓ Могу ли я хранить список стран в Zustand вместо Redux?

Да.

### ❓ Какая ветка и цель для PR?

Работайте в `forms`, откройте PR в `main`.

### ❓ Что именно понимается под неконтролируемой формой здесь?

Входные данные не управляются состоянием React (value). Считывайте значения через FormData, обработчик onSubmit/onChange формы или ref.

### ❓ Нужно ли отключать кнопку отправки в неконтролируемой форме?

Нет. Выполняйте валидацию только при отправке.

### ❓ Могу ли я прикрепить обработчики onChange в неконтролируемой форме?

Да, при условии, что вы не устанавливаете значение input программно.

### ❓ Должна ли неконтролируемая форма быть реализована без React Hook Form?

Да. Неконтролируемая = без RHF; другая форма = с RHF.

### ❓ В форме RHF должна ли кнопка отправки быть отключена при наличии ошибок?

Да, живая (мгновенная) валидация должна отключать отправку.

### ❓ Является ли загрузка изображения обязательной?

Считайте её обязательной и проверяйте тип/размер, затем сохраняйте как base64.

### ❓ Как преобразовать загруженное изображение в base64?

Используйте FileReader.readAsDataURL и сохраните результат в хранилище.

### ❓ Допустимо ли использовать <input list> с <datalist> для автодополнения страны?

Да, но список стран должен храниться в хранилище, и значение должно проверяться на соответствие этому списку.

### ❓ Должно ли автодополнение принимать только значения из списка?

Да, проверьте, что выбранное значение существует в сохраненном списке.

### ❓ После повторного открытия модального окна должны ли поля быть предзаполнены предыдущими данными?

Нет. После успешной отправки при повторном открытии форма должна быть пустой.

### ❓ Какие требования к доступности для модальных окон?

Ловушка фокуса, возврат фокуса на элемент, вызвавший окно, закрытие по ESC и закрытие по клику вне окна.

### ❓ Нужно ли мне использовать useEffect для состояний загрузки/ошибки?

Нет. Используйте библиотеку форм/состояние и ошибки схемы; не нужно управлять значениями вручную.

### ❓ Как тестировать загрузку файлов?

Используйте userEvent.upload с экземпляром File в тестах RTL.

### ❓ Должны ли все обязательные поля отображаться в обеих формах?

Да. Обе формы собирают одинаковые данные и валидируют в соответствии со схемой.

### ❓ Должны ли обе формы использовать одну и ту же схему валидации (Yup или Zod)?

Да. Примените выбранную схему к обеим формам.

### ❓ Насколько строгой должна быть проверка email в этой задаче?

Сделайте её намеренно минимальной. На данном этапе обучения проверяйте только базовую структуру:

- ровно один @
- непустая локальная часть до @
- домен содержит хотя бы одну точку (например, example.com)
- Избегайте регулярных выражений. Не проверяйте с помощью regex. Реализуйте понятные пошаговые проверки, которые вы и проверяющие сможете прочитать (разделите по @, убедитесь, что части не пустые, проверьте, есть ли точка в домене и т.д.).

### ❓ Как валидировать пароль и подтверждение пароля с помощью Zod в реальном времени?

Используйте refine/superRefine с watch для сравнения полей.

### ❓ Блокирует ли сложность пароля отправку?

Не требуется. Только несовпадение паролей (и другие ошибки схемы) должны блокировать отправку.

### ❓ Как показать сложность пароля в неконтролируемой форме?

Покажите индикатор через onChange формы/поля ввода или покажите сводку после отправки с ошибками.

### ❓ Могу ли я реализовать индикатор сложности пароля в виде текста вместо прогресс-бара?

Да. Подойдет любой понятный индикатор.

### ❓ Как должна обрабатываться фокусировка в формах (например, использование Tab для навигации по полям ввода)?

Убедитесь, что все интерактивные элементы формы (поля ввода, кнопки, выпадающие списки) доступны и навигируемы с помощью клавиши Tab. Порядок обхода должен соответствовать логической последовательности полей формы. Избегайте удаления элементов из порядка обхода (например, с помощью tabIndex={-1}), если это не требуется для доступности. Это позволяет пользователям эффективно перемещаться по форме и взаимодействовать с ней, используя только клавиатуру.
